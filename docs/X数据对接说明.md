# X 帖子数据对接说明

给数据提供方看的。现有两份样例（2026-11-10、2026-11-11）的格式可以直接用，下面是希望固定下来的约定。

## 送达方式

- 一个固定的下载地址，文件名带日期：`…/<YYYY-MM-DD>.json`。
- 每天一个文件，北京时间 10:00 前就绪（样例的 `fetch_time` 是 09:30 左右，监测任务 10:30 运行）。
- 如果需要鉴权，请提供一个只读令牌，按 `Authorization: Bearer <令牌>` 的方式校验。
- 请说明这个地址是否只有内网能访问。

## 文件格式

沿用样例：顶层有 `date`、`fetch_time`、`records`；每条记录至少有这些字段：

| 字段 | 说明 |
|---|---|
| `tweet_id` | 帖子编号 |
| `link` | 帖子地址，形如 `https://x.com/<账号>/status/<编号>` |
| `publish_time` | 发布时间。样例里是 UTC，请保持不变 |
| `full_text` | 正文全文 |
| `desc_links` | 正文里的链接。现在是字符串形式的列表（`"['https://t.co/…']"`），可以保持，也可以改成真正的数组 |
| `views`、`likes`、`comments`、`shares` | 抓取时的数值 |
| `author`、`author_id` | 作者 |
| `source_api` | 来源：列表还是推荐流 |

## 希望补充的（有的话）

1. **引用帖和回复对象的编号**。很多游戏帖是转述，原帖里才有试玩链接。
2. **展开后的链接**。`t.co` 短链现在要逐个展开，如果抓取时能拿到原始地址，请一起给。
3. **同一作者串内的后续帖子**。合集帖的内容都在串里，例如"我用新模型做了这些东西"这类帖子，首帖没有任何链接。
4. **列表里有哪些账号**。爆款网页游戏几乎都首发在开发者本人的账号上，列表覆盖不到的开发者，这条线会漏。如果能提供账号清单，我们可以把已知的游戏开发者补进去。

## 两条没抓到的例子（2026-11-12）

下面两条帖子在 11-10、11-11 的两份数据里都没有（发布时间晚于抓取时间，要看之后的批次里有没有）：

- `https://x.com/threejs/status/2120448192324276227`：@threejs 官方账号转发的作品，带试玩链接。
- `https://x.com/scottstts/status/2120549388745379867`：开发者展示用 three.js 和 Fable 5.2 做的作品，约 1 万浏览。

这类帖子的共同点是浏览量不高、但出自固定的一批账号。希望抓取范围里包含：

- @threejs 官方账号（它每天转发多款网页作品）；
- 已收录游戏的开发者账号（清单见 `data/games.json` 里各款的 `x_handles`）；
- 正文同时出现 three.js / WebGPU 和模型名（Fable、Claude、Codex 等）的帖子，不设浏览量下限。

抓取范围暂时覆盖不到的，可以把帖子链接写进 `data/x_manual_posts.json`，会和每日数据走同一套判断。

## 我们怎么用

每天从约 200 条里按关键词和链接粗筛出二三十条，判断是不是在讲一款能在浏览器里玩的游戏，再顺着帖子找到试玩链接。帖子内容只做字符串匹配和链接解析。
