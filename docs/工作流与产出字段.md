# 工作流、分工和产出字段

2026-11-12 的状态。网页暂停生成（`config.json` 的 `site.enabled` 为 `false`），现在的产出是数据文件和汇总文本。

## 谁做什么

定时任务不调用模型。脚本每天跑，Claude 会话每周做一次核验。

| 步骤 | 谁做 | 做什么 | 判断依据 |
|---|---|---|---|
| 1. 采集固定渠道 | 脚本，每天 | 读 10 个渠道，留下过入库线的线索 | `config.json` 里的入库线 |
| 2. 接入 X 帖子 | 脚本，每天 | 关键词和链接粗筛；展开短链；判断是游戏、待定还是不是；找试玩链接；转发帖追到原帖 | 关键词表、链接落在哪类站点、读者备注 |
| 3. 合并去重 | 脚本，每天 | 按试玩链接合并各渠道的线索；剔除已收录的和仿冒域名 | 链接归一化后的去重键 |
| 4. 判断是不是网页游戏 | 脚本，每天 | 已知游戏平台直接算；其他站点打开页面找画布或游戏引擎 | 页面和脚本的内容 |
| 5. 入库并标重点 | 脚本，每天 | 生成条目；重读 X 来源帖浏览数；达到重点线的标重点 | `config.json` 里的重点线 |
| 6. 出汇总 | 脚本，每天 | 日汇总和周汇总文本 | — |
| 7. 判断拿不准的帖子 | Claude 会话，每周 | 规则判为"待定"的帖子：是不是游戏、能不能网页玩、有没有 AI 证据 | 读帖子原文和串内内容 |
| 8. 找试玩链接 | Claude 会话，每周 | 用浏览器打开原帖，看串内和回复里的链接 | 公开接口读不到回复 |
| 9. 核验自动入库的条目 | Claude 会话，每周 | 试玩、起名、写类型和玩法介绍、归到七个方向、定 AI 标签；不是游戏的剔除 | 游戏页面和来源 |
| 10. 确认 | 用户 | 入库线和重点线的数字；拿不准的归类；重点游戏的最终判断 | — |

第 7 到 9 步的结论写回数据文件，下一次合并时生效：判为不是游戏的条目会被撤下，找到链接的会把"按帖子入库"的条目换成游戏链接。

脚本做不了、只能靠会话的事：

- 帖子只带视频、没有链接时，判断那是不是一款游戏。
- 读串内和回复里的链接。
- 写任何描述性的文字（类型、玩法、技术）。脚本只会原样引用页面或帖子的原文。
- 判断"玩法有新意"这类重点理由。

## 产出文件

| 文件 | 内容 | 谁写 |
|---|---|---|
| `data/games.json` | 收录库，一款游戏一条 | 脚本新增和刷新数字；会话补文字 |
| `data/candidates.json` | 线索队列，每条线索现在的状态和原因 | 脚本；会话可以改状态 |
| `data/sources.json` | 每条线索的出处和读到的数字 | 脚本 |
| `data/x_judgments.json` | X 帖子的核验结论 | 会话 |
| `raw/<渠道>/<日期>.json` | 每天各渠道读到的原始线索 | 脚本 |
| `digest/daily-<日期>.txt`、`weekly-<周一>.txt` | 日汇总和周汇总文本 | 脚本 |
| `data/runlog.json` | 每天各渠道的线索数，用来发现渠道失效 | 脚本 |

## 收录库的字段（`data/games.json`）

| 字段 | 含义 | 谁填 |
|---|---|---|
| `id`、`name` | 编号和名称 | 脚本取页面标题或帖子里的名字；会话可改 |
| `url`、`key` | 试玩链接和去重键。没找到链接时是来源帖子的地址 | 脚本 |
| `link_status` | `ok` 有试玩链接；`none` 没找到；`repo` 只有代码仓库 | 脚本 |
| `date_text` | 首次公开或发帖日期 | 脚本 |
| `first_seen` | 首次发现的日期和渠道 | 脚本 |
| `added`、`issue` | 入库日期和所属的周 | 脚本 |
| `stats` | 数字，每项有名称、数值、是否口径存疑 | 脚本；会话可补 |
| `stats_date` | 数字的读取日期 | 脚本 |
| `sources`、`source_posts`、`x_handles` | 出处链接、来源帖子、相关账号 | 脚本 |
| `reasons` | 入库理由，每个渠道一句 | 脚本 |
| `signals`、`hot`、`hot_since` | 达到了哪条重点线、是否重点、哪天升为重点 | 脚本；会话可以手动标 |
| `ai_tag`、`ai_evidence` | AI 标签（参与、疑似、非 AI、待确认）和证据原文 | 脚本按关键词和平台给初值；会话确认 |
| `quote`、`quote_src` | 页面或帖子的原文引用 | 脚本 |
| `kind`、`play`、`tech` | 类型、玩法介绍、技术说明 | 会话 |
| `group` | 七个方向之一，或"待归类" | 会话 |
| `xcheck` | 数据交叉验证的结论 | 会话 |
| `src` | 数据来源的文字说明 | 脚本给渠道名；会话可改 |
| `icon`、`shot`、`extra_shots` | 图标和画面截图的文件名 | 脚本只给重点条目抓图；会话可补 |
| `status` | `auto` 自动入库待核验；`verified` 核验过 | 会话核验后改 |

## 线索队列的字段（`data/candidates.json`）

| 字段 | 含义 |
|---|---|
| `status` | 收录、观察、候选、已在库、拒绝 |
| `reasons`、`reject_reason` | 现在这个状态的原因 |
| `leads` | 各渠道的线索：渠道、出处链接、数字、发布日期、是否过入库线、AI 线索原文 |
| `hard` | 两项检查的结果：是不是网页游戏、是不是近期 |
| `page` | 打开试玩页面读到的标题、描述、是否找到游戏引擎 |
| `x_now` | X 来源帖最近一次重读的浏览数 |
| `game_id`、`library_id` | 对应收录库里的哪一条 |
| 人工字段 | `manual_signals`、`ai_tag_manual`、`name_manual`、`is_game_manual`、`note` |

## 汇总文本的内容

日汇总和周汇总的格式相同：累计收录数、新增数和其中的重点数；重点条目逐条列出（名称、AI 标签、前两项数字、链接）；当天或当周升为重点的旧条目；其他新入库的前 12 条；观察中的线索名。
