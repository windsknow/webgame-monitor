# 重点评判规则（2026-11-25 定稿）

用户定的方向（原话）："热度只用X浏览数据判定，其他平台主要选用标准还是看玩法是否够新或技术是否够前沿……主要问题是fable52游玩数据太低，Astrocade则是数据太高但很多都是很简单的小游戏"

这份文档取代 README 旧版的"标为重点"一节，以及 `docs/入库线和重点线的数据依据.md` 里的重点线部分。门槛数字在 `config.json` 的 `thresholds.hot`、`x_spread`、`platform_hit` 和 `prescreen`，代码在 `monitor/merge.py` 的 `signals`、`verified_x`、`judge`、`prescreen`。

## 一、什么算重点

满足任意一条就是重点。几条同时成立时，卡片上全部列出，例如"X 热度 449.3 万 · 技术强"。

| 入选理由 | 条件 |
|---|---|
| X 热度 | 单帖浏览 ≥ 20 万 |
| 玩法新 | 玩法新颖（N）评分 2 分 |
| 技术强 | 技术前沿（T）评分 2 分 |

不算重点的情况：
- 2 分记了"待核"；
- 技术 2 分来自"同类移植"中没被选中的那几款。

已核验卡片也按这条规则重算，原来人工标的重点不再自动保留。

### 只做展示、不算重点的标签

| 标签 | 条件 |
|---|---|
| X 有传播 | 单帖浏览 5 万到 20 万 |
| 平台爆款 | Astrocade 游玩 ≥ 50 万次 |
| 待核 | N 或 T 可能够 2 分，但依据不足，见第三节 |
| 同类移植 | 同一原作有多款移植，重点只取一款，见第四节 |

"平台爆款"的门槛按平台分布定。Astrocade 热门页 2026-11-12 至 11-25 出现过 177 款：
- 最高游玩数前 10% 约 16 万，前 5% 约 57 万；
- 取 50 万，约前 5%；
- 按 11-19 的数据，库里有 3 款达到：Stickman Archer、Apex Strike、Steal an Egg。

其他平台的游玩数量级小得多（Spawn 最高约 4,000），暂不设"平台爆款"。

游玩数、Hacker News 分、GitHub 星照样显示在卡片上，只作参考，不决定重点。每周复核排队时可以用游玩数排先后。

## 二、X 浏览怎么取

- **可以算的帖子**：
  - 作者本人发的帖子；
  - 别人专门介绍这款游戏的帖子（`data/fable52_x_posts.json` 里 `kind` 为 `third_party`，卡片写"他人介绍帖"）。
- **取哪个数**：卡片关联的所有可以算的帖子里，浏览最高的那条。
- **不算**：多款游戏的清单帖，只出现在清单帖里的游戏记在 `not_found`。
- **重读频率**：
  - 发帖 14 天内的 X 渠道来源帖，每天重读；
  - 其余关联帖子每 7 天用 fxtwitter 公开接口重读一次，不需要登录。这包括二手渠道溯源到的作者帖或他人介绍帖，以及已核验卡片的 `source_posts`。
- **读数存放**：`data/state/x_reads.json`，记的是实际读取那天的日期。
- **卡片显示**：X 数字下面标"MM-DD 读取"。
- **只涨不跌**：浏览数只取读到过的最大值。过了 20 万线以后一直保留重点，不会因为重读进进出出。
- **已核验卡片**：手写的"首发帖浏览""作者帖浏览"会被重读值替换，标签前加"X "，并标上读取日期。

## 三、玩法新颖（N）和技术前沿（T）怎么打分

每周在本机会话里打分，各给 0、1、2 分，每个分数写一句依据并注明来源类型。

### 玩法新颖 N

| 分 | 标准 | 例子 |
|---|---|---|
| 0 | 经典小游戏换皮，或模板玩法 | 井字棋、三消、2048、合成、点击放置、Flappy、贪吃蛇、模板 Tycoon、换装、踢打玩偶、问答测验、Obby；常见类型的标准做法（普通 FPS 打靶、普通赛车） |
| 1 | 常见类型，有一处明确的新做法 | 少见题材配相应的机制改动；两个常规玩法的组合；真实世界数据做内容、玩法常规 |
| 2 | 核心机制在主流网页游戏门户的头部里很少见 | 罕见核心机制（摄像头追踪手部当输入、用一个系统讲清现实中的一套运作原理）；跨类型组合本身就是核心；运行时 AI 的应用方式新颖；真实世界数据带来新机制 |

N 的几条细则：
- **移植和复刻不算玩法分**：移植作品的玩法就是原作，只在 T 里计。
- **真实世界数据**：
  - 套用已有玩法、只把内容换成真实数据的给 1 分。例如：
    - 猜地点、猜年代：EraGuessr、WenWare；
    - 真实地图上开车、开坦克：Hop.Earth、World Strike；
    - 真实城市里自由行走或探索：San Francisco、Tiny València、Earth；
    - 真实机场和天气的飞行模拟：Open Skies、OpenAero DFW。
  - 真实数据带来新机制的给 2 分。例如：
    - Roadarium：车流按各国真实交通规则运转；
    - Boring Game：造价和审批成为玩法，目前记待核。
- **运行时 AI**：
  - AI 只是可选功能，但应用方式本身新颖的，也可以给 2 分。例如 Scam With Your Friends，大模型扮演来电者和玩家自由对话。
  - AI 只做一次性的内容生成、不参与运行的，不按这条算。
- **体量小、机制少见的小品**：先给 1 分，并在 `recheck` 里写"试玩确认机制少见后可升到 2 分"。例如 Fable52 上日本作者的一组解谜：「うしろのハニワ」「REEL DELVE」「LUMEN REEL」「ぽん、と森は灯る」「切りもどし」。

### 技术前沿 T

| 分 | 标准 |
|---|---|
| 0 | 常规 2D 或 DOM 实现；平台模板直接生成的简单 3D |
| 1 | 有一项明确的亮点：完整 3D 场景带物理、小规模多人房间、程序化地图、单个 HTML 做出较完整的游戏 |
| 2 | 达到前沿：端游级 3D 表现（大场景、光照阴影、WebGPU、写实材质）；几十人以上同场或实时匹配对战；整个世界程序化生成；运行时用大模型；反编译或移植有难度的作品（主机或 PC 老游戏、大型网游）；一次生成完成度极高并有公开过程（模型、声音、贴图都由代码生成） |

T 的几条细则：
- **技术名不等于表现力**：只写了 three.js、WebGPU 这类技术名，或者只靠前端代码特征识别出来的，T 最高给 1 分。
- **一次生成要求素材也由代码生成**：素材是图像模型生成或外部导入的，不算"完成度极高"，最高给 1 分。例如 Aiden's Revenge 用了 ChatGPT Images 生成图片，T 给 1 分。

### 依据规则

- **来源类型**：每个分数写明依据来自哪类来源：
  - 视频抽帧；
  - 试玩；
  - README；
  - 作者帖文或博客；
  - 游戏自己页面上的说明；
  - 基线报告；
  - 人工复核。
- **2 分的依据**：必须来自上面这些来源。
- **待核**：2 分如果只来自合集站或平台的一句话简介、清单描述，或只靠前端代码特征，就记"待核"（打分文件里写 `"pending": ["N"]`）。
  - 待核不算重点。
  - 卡片上标"玩法新待核"或"技术强待核"。
  - 下周补视频或试玩后再定。
- **判 0 分**：游戏自己的简介已经写明是换皮玩法的，可以直接判 0，不要求试玩。
- **待定**：依据不足、判断不了的记 `null`，不给分。
- **拿不准**：在两档之间的取低的一档。
- **已核验卡片**：基线报告里的 `play`、`tech` 是人工核验过的，可以直接当依据。

## 四、同类移植

同一个原作有多款网页移植时，只取完成度最高的一款作为重点。其余的打分文件里写 `dup_of`（被选中那款的 id）和 `dup_note`，卡片标"同类移植"。

现在的一组是 Quake 系 3 款，取 Quake-SRP：
- Quake-SRP：整个引擎重写成无依赖的安全 Rust 再编译成 WASM，共享版第一章可玩，Hacker News 241 分。
- Three.js Quake：同为共享版第一章的完整移植。
- Quake 3 WebGPU 版：现代渲染重制，链接是源码仓库，没有确认能在线玩。

## 五、每天预筛和每周终判

### 每天预筛（不调模型）

`merge.py` 的 `prescreen` 给还没打过分的自动卡片写 `prescreen: {level, why}`。它只决定复核的先后，不决定重点。

| 档 | 条件 |
|---|---|
| 降级 | 命中换皮关键词，又没有复核技术标签；Astrocade、Spawn、Verse8 的卡片命中换皮关键词，或不在平台榜前 5 |
| 优先 | 有复核技术标签（WebGPU、WASM、多人或联机、大模型、程序化、移植或反编译、摄像头、真实地图等）；或有作者帖子、源码仓库、视频 |
| 普通 | 其余；以及 Astrocade、Spawn、Verse8 上没命中换皮关键词、在榜前 5 的 |

关键词表在 `config.json` 的 `prescreen`。three.js 不算复核技术标签：Fable52 上 86 款里有 67 款都有。

### 每周终判

1. 列出要打分的卡片：`python3 scripts/apply_novelty.py --queue`。按优先、普通、降级的顺序列出还没打分的卡片，以及上周记了待核或 `recheck` 的卡片。
2. 用 Sonnet 子代理按第三节打分，主会话复核所有 2 分和所有待核。
3. 结果写进 `data/novelty/<日期>.json`，格式见 `scripts/apply_novelty.py` 开头的说明。
4. 跑 `python3 scripts/apply_novelty.py data/novelty/<日期>.json`，再跑 `python3 run.py merge`。
5. 跑 `python3 run.py feed`。

人工备注（以前的 `manual_signals`、`hot_manual`）不再单独让卡片成为重点，改成 N、T 的依据，按同一标准打分。
